# Пример: проверки плана и проектные гейты на двух стеках

> Иллюстрация контракта [`../SDLC.md`](../SDLC.md) → Верификация → «Проверки плана и проектные гейты».
> Виток TASK-001 меняет два модуля с разными стеками: сервис `ledger-svc` (JVM, сборщик `gw`)
> и приложение `cabinet-web` (JS, пакетный менеджер `npm`). Одна команда — не заменяет другую.
> Все имена и данные вымышленные.

## Условие

План витка закрепляет две разные проверки. Проектный гейт «Тесты» проверяет инварианты
баланса фронтенда и не знает про тесты сервиса.

Выдержка из `gates.md` этого вымышленного проекта:

| Гейт | Вкл | Где отчитывается | Чем реализован |
|---|---|---|---|
| Сборка | да — минимум | этап 6 | `./tools/gw build -x test` |
| Тесты | да — минимум | этап 6 | `npm run validate --workspace cabinet-web` |

Выдержка из `plan.md` (карточки шагов и «Чем закрывается каждый пункт приёмки»):

```
### Шаг 1 — пересчитать баланс
- файл: ledger-svc/src/main/kotlin/acme/ledger/BalanceRecalculator.kt (существующий)
- закрывает: claim-1
- проверка: ./tools/gw :ledger-svc:test --tests 'acme.ledger.*' из корня репозитория · ожидаемо: зелёный

### Шаг 2 — показ пересчитанного баланса
- файл: cabinet-web/src/balance/view.ts (существующий)
- закрывает: claim-2
- проверка: npm run validate --workspace cabinet-web из корня репозитория · ожидаемо: зелёный
```

| Пункт | Чем закрывается |
|---|---|
| claim-1 | исполняемая: `./tools/gw :ledger-svc:test --tests 'acme.ledger.*'` из корня → 12 тестов зелёные |
| claim-2 | исполняемая: `npm run validate --workspace cabinet-web` из корня → инварианты баланса зелёные |

## Попытка 1 — результат нельзя принять

Исполнитель прогнал гейт «Тесты», поставил его зелёным в свидетельство и не запускал
команду плана для `ledger-svc`.

Таблица «Гейты» отчёта:

| Гейт | Статус | Результат |
|---|---|---|
| Сборка | ✅ | `./tools/gw build -x test` · код 0 · вывод `chunk-1-attempt-1-tests.txt` |
| Тесты | ✅ | `npm run validate --workspace cabinet-web` · код 0 · 14 инвариантов зелёные · вывод `chunk-1-attempt-1-tests.txt` |
| Scope: файлы вне плана | ✅ | нет (`.sdlc/**` исключены) |
| Анти-обход тест-гейта | ✅ | маркеров отключения нет |
| Ревью независимым агентом | ✅ | модель сильнее исполнителя; на входе задача, план, набор и diff |

Таблица §1 отчёта:

| id | Пункт (первые слова, дословно) | passed | Чем подтверждён (`файл:метод` / тест / hunk диффа / команда · вывод) | Что чинить |
|---|---|---|---|---|
| claim-1 | Пересчёт баланса при… | ⚠ | `./tools/gw :ledger-svc:test --tests 'acme.ledger.*'` не выполнялся; зелёный вывод `npm run validate` — команда гейта другого стека, закреплённую процедуру не заменяет | запустить команду плана из корня и сохранить вывод |
| claim-2 | Показ пересчитанного… | ✅ | `npm run validate --workspace cabinet-web` · код 0 · дерево `e7d03b1` · вывод `chunk-1-attempt-1-tests.txt` | н/п |

Вердикт: **passed: false** — claim-1 в `⚠`. Пять зелёных гейтов вердикт не подняли:
обязательства независимы, итог определяется слабым звеном.

По требованию ревью отдельный прогон `./tools/gw :ledger-svc:test --tests 'acme.ledger.*'`
на том же дереве дал 11 из 12. Это не меняет статус попытки 1: результат другой редакции
прогона сам по себе не свидетельство попытки, но показывает, что зелёный гейт фронтенда
скрывал бы красный сервисный тест, будь он выполнен.

## Попытка 2 — результат можно принять

Исполнитель запустил обе закреплённые процедуры и сохранил выводы.

Таблица §1 отчёта:

| id | Пункт (первые слова, дословно) | passed | Чем подтверждён (`файл:метод` / тест / hunk диффа / команда · вывод) | Что чинить |
|---|---|---|---|---|
| claim-1 | Пересчёт баланса при… | ✅ | `./tools/gw :ledger-svc:test --tests 'acme.ledger.*'` из корня · gw 8.10 · дерево `e7d03b1` · 12/12 · вывод `chunk-1-attempt-2-tests.txt` | н/п |
| claim-2 | Показ пересчитанного… | ✅ | `npm run validate --workspace cabinet-web` · код 0 · дерево `e7d03b1` · вывод `chunk-1-attempt-2-tests.txt` | н/п |

Вердикт: **passed: true** — каждая проверка плана выполнена на закреплённом патче,
команда, каталог, среда и адрес вывода видны по артефактам.

## Что видно по артефактам этого примера

- **Команда гейта живёт в наборе, результат — в таблице «Гейты» отчёта.** Видно, что выполнено:
  `npm run validate --workspace cabinet-web`, код 0.
- **Команда проверки плана живёт в плане, фактический запуск — в §1 отчёта.** Видно, какая
  команда запускалась, из какого каталога, на какой ревизии и где сохранён вывод.
- **Зелёный гейт другого стека пункт не подтверждает.** Попытка 1 отклонена при пяти зелёных
  гейтах, потому что закреплённая процедура claim-1 не выполнялась.
- **Принимается только слабое звено.** В попытке 2 обе процедуры зелёные — вердикт поднят.
  Будь сервисный тест красным (11/12), тот же набор гейтов дал бы `passed=false` с `❌`.
- **Отдельный прогон — не свидетельство попытки.** Он либо становится новой попыткой
  с собственным журналом и выводом, либо остаётся замечанием ревью.
