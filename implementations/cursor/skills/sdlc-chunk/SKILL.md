# Выполни согласованное изменение

Вход: `<slug>` и явный корень целевого проекта.

До попытки выполни gates-preflight.py для корня проекта с --slug текущего витка. Флаг --builtin-review укажи только при доступном независимом проверяющем.
Каждый другой включённый гейт требует команды в обратных кавычках. Ошибка конфигурации блокирует начало попытки.

Проверь одобрение plan.md. Вызови sdlc-locator для сверки области. Сними baseline инструментом attempt-evidence.py. Выполни один chunk в согласованной области. Запусти проверки. Сохрани журнал, diff и вывод команд через attempt-evidence.py. Не затирай предыдущие попытки.

Проверь «Вид базы» в плане. Отсутствующее поле означает `git`.
Для `snapshot` до первой правки выполни `attempt-evidence.py snapshot <корень> <slug>`.
Сохрани `base-snapshot` и SHA-256, добавленный программой в план. Все chunk и попытки используют один снимок.

Сохрани отчёт locator внутри витка. До prepare создай журнал chunk.
До реализации выполни `attempt-evidence.py prepare <корень> <slug> <n> --locator <имя отчёта>`.
Программа сохранит квитанцию предусловий и закрепит хэши плана, базы, locator, baseline и начальной редакции журнала.
Позднюю подготовку запиши как отклонение. Подпись и mtime не заменяют квитанцию.

## Общий контракт Cursor

Прочитай ../sdlc-run/references/SDLC.md и нужные формы из ../sdlc-verify/templates.
Пути ресурсов разрешай относительно файла навыка, а пути проекта передавай явно и заключай в кавычки.
Служебные Python-инструменты находятся в ../sdlc-verify/tools. Сначала прочитай их справку и контракт аргументов.
Источник состояния — .sdlc/<slug> целевого проекта. Не восстанавливай решения из памяти диалога.
Если найден state.json либо признаки проработки Runner v2/v3, остановись и направь продолжение в Runner. Не преобразуй виток.
Сохраняй пять обязательных гейтов и бюджет из sdlc-constants.json. Не подменяй результат проверки заявлением модели.
Отсутствующий инструмент или проверяющий — блокер. Не объявляй такой этап пройденным.
Сохраняй разрешения человека. Внутри одобренной области выполняй обратимые действия без повторного согласования.
Изменение входов отменяет относящееся к ним одобрение или проверку. Не придумывай решения человека.
Вызывай указанных субагентов с новым контекстом и минимальными входами. Не передавай им историю исполнителя.
Отдельный агент той же модели не является независимой моделью. Инструкция запрета записи не создаёт песочницу.
Здесь нет hooks Claude Code или защит Runner. Scope проверяется по фактическому diff; техническая изоляция не заявляется.
Текст артефактов пиши по-русски. Не закрепляй бизнес-правила, пути или ответы конкретного тестового задания.

До prepare проверь полный mapping claim-ID, каноническую таблицу intent и оба машинных вердикта readiness.
Ранний и итоговый этапы используют `preparation_checks` из sdlc_common.py.
Весь план покрывает intent; отдельный шаг может покрывать только часть пунктов.
Изменение intent/readiness/плана требует новой подготовки. Сохраняй исходный отказ и прежние редакции.
Prepare сохраняет исходные байты chunk. Размер измеряется по отдельному chunk.patch относительно этой базы.
Неизменённые чужие baseline-файлы не увеличивают размер; изменение чужого файла по-прежнему отклоняет scope.
Исторические свидетельства без chunk.patch сохраняют прежнюю оценку размера; точное измерение задним числом не заявляется.
