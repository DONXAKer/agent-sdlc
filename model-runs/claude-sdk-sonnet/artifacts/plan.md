## Подход
_Одно-два предложения: как решаем. Нашёлся на разведке готовый механизм — здесь сказано, что мы его
используем, а не пишем свой._

Правило негабарита и его ставки выносим в новый модуль `src/oversize.ts`, оформленный по
образцу `src/zones.ts`; он считает надбавку в копейках через `percent`/`add` из `money.ts`
(то же округление, что и у скидки), не заводя собственной арифметики. `tariffs.ts` вызывает уже
имеющиеся в нём `longestSide`/`dimensionSum`, передаёт готовые числа в `oversizeSurcharge` и
добавляет поле `surcharge` в `Quote` только когда оно определено — без циклического импорта
между `tariffs.ts` и `oversize.ts`.

## Шаги
_Каждый шаг — проверяемое действие. «Использовать ‹символ›» — обязательная форма для всего, что
нашлось на разведке._

1. Использовать `src/money.ts:percent` и `src/money.ts:add`/`src/money.ts:subtract` — новый модуль
   и `priceFor` считают надбавку и итог этими функциями, без своего округления и без голых `+`/`-`.
2. Использовать `src/zones.ts` как образец оформления модуля (doc-комментарий с инвариантом,
   именованные константы и функция-экспорт без `default export`) для нового `src/oversize.ts`.
3. Создать `src/oversize.ts`: константы порогов (120 см, 300 см) и ставок (40%, 90%); функция
   `oversizeSurcharge(longestSideCm: number, dimensionSumCm: number, base: Kopeck): Kopeck |
   undefined` — `undefined`, если оба условия «не строго больше»; иначе ставка 90%, если сумма
   строго больше 300 см (в том числе когда сработали оба условия — не складывать), иначе 40%.
4. Не импортировать `src/tariffs.ts:longestSide`/`dimensionSum` внутрь `oversize.ts` —
   привело бы к циклическому импорту `tariffs.ts → oversize.ts → tariffs.ts`, который ловит
   `scripts/build-check.mjs` («циклы» в гейте «Сборка»). Вместо этого использовать найденное
   так: `tariffs.ts` сам вызывает уже импортированные в нём `longestSide`/`dimensionSum` и
   передаёт в `oversizeSurcharge` готовые числа, а не `Dimensions` целиком.
5. В `src/tariffs.ts`: добавить `import { oversizeSurcharge } from './oversize.ts'`; расширить
   существующий импорт из `money.ts` функцией `add`; добавить в `Quote` опциональное поле
   `surcharge?: Kopeck` с JSDoc «отсутствует, если отправление в пределах габаритов — не 0, не
   `undefined`-значение ключа»; в `priceFor` посчитать `surcharge` после `discount` и до `total`
   (порядок база → скидка → надбавка → итог, инвариант задачи), собрать `total` через
   `add(subtract(base, discount), surcharge)`, когда `surcharge` определён, иначе как раньше —
   `subtract(base, discount)`; вернуть объект **одним из двух раздельных литералов** (с ключом
   `surcharge` или без), не присваиванием `undefined` в существующий объект (иначе ключ
   физически появится и `claim-1`/`claim-5` упадут на `Object.keys`).
6. Написать `test/oversize.test.ts`: локальную фикстуру `order()` по образцу
   `test/tariffs.test.ts:order` (повторить, не импортировать — файл фикстуры не входит в
   `files_to_touch` на правку, и делать его экспортируемым мы не вправе; это копия тестовых
   данных, не второй экземпляр расчётной логики); тесты на `claim-1` (доп. явная проверка
   `Object.keys(quote).sort()`), `claim-2`…`claim-7` — каждый через `priceFor(order({...}))` с
   ровно теми входами и ожидаемыми числами, что в `intent.md`.
7. Прогнать `npm run build` (`node scripts/build-check.mjs`, ловит в т.ч. циклический импорт,
   если шаг 4 не соблюдён) и `npm test` (`node --test "test/**/*.test.ts"`); вывод команд — в
   журнал этапа 6. Проверить, что `git diff` по `test/tariffs.test.ts` и `test/money.test.ts`
   пуст.
