## 1. Пункты приёмки

_`✅` — доказано по diff или тестом. `❌` — опровергнуто. `⚠` — доказательство держится
на непройденной проверке. Статус выбирается по тому, **на чём держится доказательство**: пункт,
доказуемый по diff, получает `✅` даже при непрогнанном тесте. Новые id не создаются — работаем
строго по id из задачи._

| id | Пункт | passed | Чем подтверждён (`файл:метод` / тест) | Что чинить |
|---|---|---|---|---|
| claim-1 | ‹пункт› | ‹✅/❌/⚠› | ‹Файл:метод / ИмяТеста› | ‹что чинить› / н/п |

## 2. Ревью: что искали опровергнуть

_Углы: построчный скан diff · аудит удалённого поведения · кросс-файловый трейс вызывающих
и вызываемых._

- Подтверждённое расхождение: ‹что не совпало, с адресом› / н/п
  _(роняет вердикт независимо от пунктов приёмки)_
- Поведение, не покрытое ни одним пунктом: ‹что именно› / н/п
  _(это ещё и пропуск в приёмочном листе — идёт в запись о дефекте, а не на ближайший по смыслу пункт)_

## 3. Scope

- Файлы вне `plan.files_to_touch`: ‹список› / нет
- «Чего не делаем» просочилось в diff: ‹что именно› / нет
- **Пути плана без правок** — на каждый одна из двух формулировок, «нет замечаний» не годится.
  Гейт в долге — сверку делает рецензент руками, шаг от этого не исчезает:
  - ‹путь из plan.files_to_touch› — «не потребовалось, потому что ‹причина›» / «не сделано»
  - непокрытых путей нет

## 4. Инварианты

_Нарушенный инвариант роняет вердикт независимо от статусов гейтов. Инвариант, для которого задача
назвала конкретный проходящий тест, закрывается этим тестом — в долге может быть гейт с ассертами,
но не сам факт наличия теста._

- ‹инвариант из задачи› — держится, чем подтверждён: ‹тест / место в diff› / нарушен: ‹где›
- проектных инвариантов в задаче нет: н/п

## 5. Регрессии

_Только откат внешнего поведения: сломанная сборка или тесты, переход пункта из `✅` в `❌`. Новый
внутренний побочный эффект, не покрытый пунктом приёмки, — это §2, а не регрессия._

- ‹что сломалось› / нет
