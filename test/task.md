# SCHED-101 — отмена задач с каскадом на зависимых

Исходная формулировка задачи, которую «человек» приносит на этап 1 e2e-прогона.

Планировщику (`scheduler/`) нужна отмена: `Scheduler.cancel(task_id)`.

Требования словами заказчика:

- отмена задачи в `PENDING`/`READY`/`RETRY_WAIT` переводит её в новое состояние `CANCELLED`
  и она никогда не исполняется;
- отмена **каскадом** накрывает всех транзитивных зависимых (ромбы — по одному разу каждый):
  они получают `BLOCKED`, событие `blocked` эмитится на каждого ровно один раз;
- задачу в `RUNNING` в синхронной модели отменить нельзя — но если она ушла в `RETRY_WAIT`,
  отмена снимает её с пробуждения (не исполняется больше ни разу);
- отмена `DONE`/`FAILED`/`BLOCKED` — ошибка `InvalidCancelError`, состояние не меняется;
- отмена неизвестного id — `KeyError`;
- ресурсы, удерживаемые отменённой из `RETRY_WAIT` задачей, к этому моменту уже освобождены —
  инвариант «после run() пул полон» обязан сохраниться;
- `run()` после отмен продолжает исполнять незатронутые ветки графа как раньше.

Не делаем: асинхронную/принудительную отмену RUNNING, персистентность, таймауты.
