# Реализация: Claude Code (скиллы + агенты)

Семь этапов [методологии](../../SDLC.md), собранные как скиллы Claude Code, и два субагента
с урезанными правами — там, где методология требует, чтобы ограничение было конструкцией,
а не инструкцией.

## Установка

```bash
cp -r skills/*  ~/.claude/skills/
cp    agents/*  ~/.claude/agents/
```

После этого в любой сессии Claude Code доступен весь цикл:

```
/sdlc-intent → /sdlc-explore → /sdlc-ask → /sdlc-plan → /sdlc-chunk → /sdlc-verify → /sdlc-handoff
```

## Состав

| Скилл | Этап | Артефакт |
|---|---|---|
| `sdlc-intent` | 1. Цель | `intent.md`, `gates.md` |
| `sdlc-explore` | 2. Разведка | `exploration-report.md` |
| `sdlc-ask` | 3. Вопросы (условный) | `clarification-report.md` |
| `sdlc-plan` | 4. План | `plan.md` |
| `sdlc-chunk` | 5. Chunk | `chunk-N-diff.patch`, `chunk-N-tests.txt` |
| `sdlc-verify` | 6. Верификация | `verification-report-N.md` |
| `sdlc-handoff` | 7. Commit | `handoff.md`, локальный коммит |

| Агент | Роль | Инструменты |
|---|---|---|
| `sdlc-locator` | точечная разведка этапа 5 — read-only по построению | Read, Grep, Glob |
| `sdlc-reviewer` | независимый рецензент этапа 6, модель сильнее исполнителя | Read, Grep, Glob, Bash (без записи в репо) |

Внутри `/sdlc-explore` работают ещё два одноразовых субагента (разведчик и claims-агент,
выводящий приёмочный лист вслепую) — они спускаются через general-purpose с промптом из скилла
и отдельных файлов не требуют.

## Как реализация отображает методологию

- **Нет артефакта — нет шага**: каждый скилл заканчивается записью файла в `.sdlc/<slug>/`
  по шаблону из своей директории `templates/`.
- **Права на шаг, а не на прогон**: `sdlc-locator` и `sdlc-reviewer` получают урезанный набор
  инструментов во frontmatter, а не обещание в промпте.
- **Автор не рецензирует себя**: `sdlc-verify` передаёт рецензенту ровно четыре артефакта —
  задачу, план, набор гейтов, diff — без рассказа исполнителя и истории его вызовов.
- **Решает человек**: одобрение плана, подтверждение места правки, приёмка вердикта и решение
  о публикации — четыре отдельных вопроса через `AskUserQuestion`, молчание одобрением не считается.

## Другие варианты реализации

Методология не привязана к Claude Code: этапы, артефакты и гейты (см. [`SDLC.md`](../../SDLC.md))
можно собрать на любом стеке — CI-пайплайн с ручными паузами, другой агентный харнесс, чек-листы
в трекере. Минимум, без которого виток не стартует: команда сборки, команда тестов, сверка diff
со списком файлов плана и проверка на обход тестов. Новые реализации добавляются соседними
директориями в `implementations/`.
