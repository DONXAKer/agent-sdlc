# Guided: выполнение малых задач одной локальной моделью

Статус: экспериментальный профиль Runner, включается только для новой задачи.
Основа — проработка v3 и семь этапов SDLC. Критерий завершения — проверенное поведение
на согласованной редакции требований, а не заполненные документы.

## Ответственность

Человек сообщает отсутствующие бизнес-правила и одобряет конкретный план. Модель
исследует код, предлагает изменения и анализирует результаты. Рантайм хранит состояние,
проверяет ограничения, применяет изменения, выполняет зарегистрированные проверки и
собирает доказательства. Одна локальная модель используется на всех этапах и в ревью.
Повышение до более сильной модели не считается успехом этого профиля.

## Цикл Деминга: Plan → Do → Study → Act

1. **Plan.** Сохранить исходный запрос. Получить проверяемые требования и основания
   из исследования. Выяснить недостающие бизнес-правила. Собрать связный план:
   файл, символ, действие, требования, проверка, ожидаемый результат, зависимости.
   Проверить план и получить одобрение человека. Рантайм объединяет зависимые шаги
   и шаги одного файла в группы: изменение контракта проверяется вместе с потребителями.
2. **Do.** Показать модели одну группу, согласованные требования и исходники с хэшами.
   Модель возвращает прогноз и точные замены. Рантайм сначала проверяет все замены
   и разрешения, затем применяет группу с журналом восстановления.
3. **Study.** Выполнить зарегистрированные проверки после всей группы. Записать
   прогноз, фактический результат, редакции требований и кода. Отсутствующая среда
   и пропущенная проверка не дают положительного результата.
4. **Act.** При расхождении модель получает результат проверки и меняет гипотезу.
   После трёх попыток — одно содержательное переразбиение, затем максимум три цикла
   проверки. Неразрешённая ошибка останавливает задачу, следующие группы блокируются.
   Обучение процесса выполняется по серии измерений; один удачный прогон не меняет стандарт.

Финальный verify повторно проверяет требования и код. Ревью отдельным запросом той же
модели уменьшает влияние истории диалога, но не обеспечивает независимость её ошибок.

## Poka-yoke: предотвращение ошибок конструкцией

| Ошибка | Ограничение рантайма |
|---|---|
| Модель переписала план или решение человека | Отдельные защищённые артефакты; одобрение только через операторский путь |
| Правка чужого файла | Белый список группы и плана, проверка пути и симлинков |
| Замена по старому коду | Хэш исходника, точное уникальное совпадение SEARCH |
| Потеря файла при переписывании | Запрет полной замены существующего файла |
| Половина группы применена до отказа | Все разрешения до записи; журнал восстановления до первой записи |
| Потеря внешней правки при откате | Восстанавливаются только известные версии собственных изменений |
| Успех без изменения там, где оно не нужно | no_change разрешён, но проверки и финальная приёмка обязательны |
| Зелёный результат от старого кода | Привязка доказательств к редакциям и повторная проверка при возобновлении |
| Бесконечные исправления | Одна починка формата, шесть чтений/поисков на группу, ограниченные попытки и время |
| Человек выполняет инженерную работу за модель | Стенд отвечает только известными бизнес-фактами; неизвестный вопрос остаётся без ответа |

На задачу отводится 30 минут активного времени; ожидание человека исключается.
Счётчик сохраняется между этапами. Это ограничение работы, а не обещание успешного решения.
После перезапуска незавершённая группа восстанавливается; одновременное редактирование
тех же файлов внешним процессом может потребовать остановки и разбора конфликта.

## Приёмка профиля

Пилот: Qwen 8B, Granite 8B, Gemma 12B; freeship, config-default, two-right-answers,
wrong-diagnosis; по три повтора legacy и guided с одинаковой проработкой v3,
моделью и банком ответов. Сохранять версию исходников, условия, все неудачи и время.
Успех: финальная приёмка, все скрытые проверки, отсутствие нарушений честности и
соблюдение времени. Ошибка среды учитывается отдельно и не становится успехом.
Целевой порог — не менее 80% на каждой модели; он пока не подтверждён.

После пилота — шесть моделей, восемь задач, пять повторов и отдельный удержанный
набор задач, не использованный для настройки. До этого guided не становится режимом
по умолчанию. Результаты известных задач нельзя выдавать за обобщение на любую модель.
