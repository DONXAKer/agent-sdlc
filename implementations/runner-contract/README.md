# Контракт рантайма Agent-SDLC v1

Канонический файл `.sdlc/<slug>/state.json` соответствует
`schemas/agent-sdlc-state-v1.schema.json`. Markdown — читаемая проекция состояния.
Схемы v1 сохранены; reference-проверка дополнительно проверяет смысловую согласованность.

## Границы ответственности

Рантайм должен атомарно записывать state, создавать попытки, запускать гейты, хэшировать
свидетельства, сохранять решения человека и вычислять вердикт. Модель предлагает данные;
ей не выдаются права изменять состояние, защищённую приёмку и свидетельства исполнителя.
Reference-инструменты **не обеспечивают эти права и происхождение данных**: необходимы
изоляция и проверка полномочий в конкретном исполнителе. Корректный JSON не доказывает,
что команда запускалась, решение принадлежит человеку или код соответствует указанной ревизии.

Рецензент возвращает JSON по `verify-review-v1.schema.json`. Исполнитель проверяет формат,
точное покрытие canonical claims, доступность свидетельств и семантику результата. Ограниченное
декодирование полезно, но не заменяет проверку; после одного неуспешного repair-запроса
обязательный review-gate остаётся непройденным.

## Проверки reference-реализации

`tools/state_contract.py validate-state <state.json>` проверяет вложенные поля, типы,
неизвестные ключи, диапазоны и форматы используемых схем v1. Дополнительно:

- `passed=true` разрешён только на verify/handoff, при `action=continue`, непустой приёмке,
  отсутствии failed/uncertain claims, открытых findings и unresolved migration;
- passed claim требует evidence; manual требует явного тега `manual` у canonical claim;
- минимальные пять гейтов должны присутствовать, быть включены и относиться к этапу 6; все включённые гейты
  до текущего этапа должны быть passed (до 6 на verify, до 7 на handoff), каждый такой
  passed-гейт требует хотя бы одного свидетельства с SHA-256;
- гейт этапа 7 не блокирует verify; skipped/debt обязательного текущего гейта блокируют успех;
- дубли `(gate.name, stage)` и `(attempt.chunk, number)` запрещены.

`passed=false` — допустимое промежуточное состояние, а не доказательство завершения.
Manual не означает автоматического принятия человеком: это статус явно ручного пункта,
который должен быть предъявлен человеку при сдаче.

CLI `flow-verdict.py` дополнительно проверяет совпадение slug и запрошенного этапа,
существование файлов evidence и SHA-256 там, где он предусмотрен схемой (гейты, попытки,
импортированные артефакты). Review-reference v1 не содержит hash: там проверяется наличие
файла, но anchor остаётся адресом для просмотра, а не доказательством корректности assertion.

## Пути свидетельств

Обычный путь (`src/service.py`) отсчитывается **от корня проекта**. Явный префикс
`artifact:` (`artifact:chunk-1-attempt-1-tests.txt`) отсчитывается **от каталога витка**.
Автоматического поиска между двумя корнями нет. Абсолютные пути, выход через `..` и
симлинки за выбранный корень запрещены. Это проверка ссылок, не полноценная песочница
и не защита от изменения файла между проверкой и последующим использованием.

`migration.artifacts` сохраняет формат v1 `путь:sha256`, путь здесь относительно каталога
витка. Импорт не доверяет legacy-вердикту: создаёт uncertain claims и unresolved migration,
которые требуют повторной проверки. Он не перезаписывает существующий output.

## Совместимость и установка

При отсутствии state `flow-verdict.py` сохраняет прежний Markdown-протокол. Если state есть,
он проверяется первым; некорректный JSON, отсутствующий validator, несовпавший hash или другая
ошибка дают отказ **без возврата к Markdown**. Устаревшие проекции не влияют на state-вердикт.
Сам state.json также должен находиться внутри корня проекта; симлинк наружу отклоняется.

В state-режиме `--print` поддерживает `action`, `attempts` (все записи массива) и `chunk`
(максимальный chunk, либо 1). `budget`, `approved`, `readiness2`, `reports`, `next_chunk` и
`all` не имеют достаточного представления в v1 и завершаются ошибкой без чтения Markdown.
Legacy-раннер, использующий эти поля, нельзя переводить на state простым созданием файла:
ему нужен собственный адаптер и явная миграция. `--metrics` остаётся наблюдением по legacy
Markdown и не используется как гейт или источник canonical состояния.

Для установки рядом с `flow-verdict.py` распространяется синхронизированная копия
`state_contract.py` и `state_contract/schemas/*.json`; канонические исходники находятся здесь.
Сверка копий включена в общий sync-процесс. Новые зависимости не требуются.

Ограничение v1: подписанная неприменимость не имеет структурированной связи с гейтом.
Reference не выводит её из текста решений: skipped обязательного гейта блокирует успех,
даже если рядом есть строка с объяснением. Для неприменимости нужна отдельно согласованная
эволюция протокола; подмена статуса на passed без выполненной проверки недопустима.
Наличие хэшированного файла подтверждает целостность доступного свидетельства, но не факт
запуска команды; это обеспечивает исполнитель. Пустой attempts сам по себе не отвергается:
reference не восстанавливает историю исполнения из догадок.
