# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за репозиторий

Документация методологии **Agent-SDLC** — как разрабатывать с агентом так, чтобы работу можно было принять. Кода и системы сборки здесь нет: это Markdown-документы на русском языке. Новый контент пишется на русском, в тоне и терминологии существующих файлов.

Цикл методологии (один проход = «виток»):

```
ЦЕЛЬ → РАЗВЕДКА → ВОПРОСЫ → ПЛАН → CHUNK → ВЕРИФИКАЦИЯ → COMMIT
```

## Структура

- **`SDLC.md`** — вся методология одним файлом: семь этапов, гейты, вердикт, словарь терминов. Первоисточник; остальные файлы должны с ним сходиться.
- **`templates/`** — **канонические** шаблоны артефактов витка, все девять: intent, readiness, exploration-report, clarification-report, plan, chunk-journal, verification-report, handoff, gates.
- **`implementations/claude-code/`** — рабочая реализация: восемь скиллов `/sdlc-intent` … `/sdlc-handoff` + `/sdlc-seed` (`skills/*/SKILL.md`) и два субагента с урезанными правами (`agents/sdlc-locator.md` — read-only разведка, `agents/sdlc-reviewer.md` — независимое ревью).
- **`example/`** — заполненные артефакты одного реального витка (Java/Spring). Виток **намеренно не принят** (ревью нашло дефект) — это часть примера, не ошибка. Артефактов этапа 5 (diff, вывод тестов) в примере нет намеренно: они порождаются кодовой базой витка.

## Правила правок (сквозные инварианты)

- **Шаблоны правятся только в корневом `templates/`**, затем разливаются скриптом `./sync-templates.sh` в `implementations/claude-code/skills/*/templates/` (`--check` — сверка). Копии в скиллах — установочные; правка «копия → корень» запрещена направлением.
- Одни и те же имена и таблицы повторяются в нескольких файлах — при изменении методологии сверяй согласованность: `SDLC.md` ↔ `README.md` (таблица артефактов) ↔ `implementations/claude-code/README.md` (таблицы скиллов/агентов) ↔ `SKILL.md` скиллов ↔ шаблоны.
- Термины и обозначения фиксированы и используются дословно: минимальный набор гейтов — «Сборка», «Тесты», «Scope: файлы вне плана», «Анти-обход тест-гейта», «Ревью независимым агентом»; пункты приёмки нумеруются `claim-1`, `claim-2`; незаполненное место — `‹…›`; «не применимо» — `н/п`; артефакты витка живут в `.sdlc/<slug>/`, артефакты попыток несут номер (`chunk-N-attempt-K-*`, `verification-report-N-attempt-K.md`).
- Ключевые принципы, на которых держится текст (не ослаблять формулировками): «нет артефакта — нет шага», «человек владеет целью, агент — исполнением», «права выдаются на шаг, а не на прогон», «автор не рецензирует себя», приёмочный лист пишет человек.

## Команды

Сборки у документов нет, но проверки есть — прогонять после правок соответствующих зон:

```bash
./sync-templates.sh            # разлить корневые шаблоны в копии скиллов (после правки шаблона)
./sync-templates.sh --check    # только сверить (гейт для CI)
make -C test/fixture test      # тесты fixture-планировщика (16 шт.)
test/run-e2e.sh [dir]          # полный e2e-прогон флоу (дорого: реальные сессии claude)
python3 test/verdict.py <run-dir> <slug>   # механический контракт флоу по готовым артефактам
```

Установка реализации — только через `./install.sh` (бэкап расходящихся глобальных версий +
честная синхронизация sdlc-*; `--check` — сверка). Голый `cp -r` не использовать: он не удаляет
убранные из репо файлы и молча затирает пользовательские правки.
