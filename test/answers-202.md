## Этап 3 (/sdlc-ask) — ответы на вероятные развилки

- «PAUSED — новое значение TaskState?» → **да, новое значение `TaskState.PAUSED`**.
- «Пауза каскадом на зависимых?» → **нет**: зависимые остаются `PENDING` естественно —
  их зависимость не `DONE`. Отдельного состояния для них не заводить.
- «Как снимать RETRY_WAIT с пробуждения — вынимать из кучи или фильтровать при выемке?» →
  на усмотрение исполнителя; критерий поведенческий: не исполняется до resume, `wake_at` исходный.
- «Что делает resume задачи, чьи зависимости уже провалились за время паузы?» → обычные правила
  `_promote_ready`: задача станет `BLOCKED` при следующем `run()`. Отдельного claim'а не нужно.
- Прочие вопросы: выбирай вариант, рекомендованный агентом, и записывай как ответ Тест-Оператора.
