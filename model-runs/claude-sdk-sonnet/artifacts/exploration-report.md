## Стек и конвенции

_Адреса кода везде в форме `файл:метод` — без номеров строк, они устаревают._

- Язык / стек: Node.js ≥23.6, TypeScript без отдельной сборки — Node исполняет `.ts` напрямую
  (импорты указывают расширение `.ts`). Внешних зависимостей нет.
- Сборка / тесты: `npm run build` → `node scripts/build-check.mjs` (загружает по очереди все
  файлы `src/*.ts`, ловит синтаксис/циклы/несуществующие импорты — не компилятор, а smoke-загрузка,
  новый файл в `src/` подхватится автоматически). `npm test` → `node --test "test/**/*.test.ts"`
  (встроенный раннер `node:test`, ассерты `node:assert/strict`).
- Конвенции: один модуль — одно узкое правило, файл назван существительным (`money.ts`,
  `discounts.ts`, `zones.ts`, `tariffs.ts`); в шапке файла развёрнутый doc-комментарий про
  инвариант модуля; именованный экспорт (`export function`/`export type`), без `default export`;
  JSDoc почти у каждого экспорта с обоснованием «почему так»; `src/index.ts` реэкспортирует всё
  из модулей плюс тонкую точку входа `quote()`.
- Требования к окружению прогона: ничего особенного — ни БД, ни сети, ни Docker; тесты и сборка
  запускаются локально одной командой `npm test` / `npm run build`.

## Найдено для переиспользования
_Самый ценный выход шага: что из нужного **уже написано**. Результат — `путь + имя символа`, а не
«наверное есть похожее». Каждая строка становится шагом плана «использовать», а не «написать».
Ненайденный хелпер порождает второй экземпляр той же логики, который потом ловится ревью как дефект._

_Отличие от карты выше: там файлы, которые мы **меняем**, здесь — символы, которые **вызываем**.
Пересечение нормально: нашёлся готовый хелпер в файле из карты — он обязан появиться и здесь._

| Символ | Где (`путь:символ`) | Что делает | Как используем |
|---|---|---|---|
| `percent` | `src/money.ts:percent` | процент от суммы в копейках, округление половины вверх | считать надбавку в новом модуле — тем же округлением, что и скидка (инвариант) |
| `add` / `subtract` | `src/money.ts:add`, `src/money.ts:subtract` | арифметика в копейках | собрать `total = base − discount + surcharge` через существующие функции, не через `+`/`-` вручную |
| `Dimensions`, `longestSide`, `dimensionSum` | `src/tariffs.ts:Dimensions`, `src/tariffs.ts:longestSide`, `src/tariffs.ts:dimensionSum` | тип и уже готовые геометрические примитивы (наибольшая сторона, сумма трёх измерений) | новый модуль `src/oversize.ts` импортирует их вместо повторной реализации геометрии |
| `zones.ts` как образец | `src/zones.ts` | пример «узкое правило → отдельный модуль»: стиль doc-комментариев, экспорт константы + функции | прямой прецедент оформления нового `src/oversize.ts` (claim-8 требует именно такое разделение) |
| `order()` | `test/tariffs.test.ts:order` | фикстура заказа с дефолтными габаритами `[20,15,10]`, msk, 900г, anonymous | образец для фикстуры нового теста — переиспользовать через импорт либо повторить по тому же шаблону в `test/oversize.test.ts` |

_Ничего подходящего не найдено: нет — для самой ставки/порога (40%/90%, 120см/300см) готового
кода не существует, эти константы и решающая функция вводятся с нуля в новом модуле; для всего
остального переиспользование найдено и перечислено выше._

## Приёмочный лист, выведенный независимо
_Заполняет **отдельный агент**, которому дали цель и границы **без авторского приёмочного листа**.
Разведчик, у которого задача целиком, «не видеть» авторские пункты не может, и его пересказ второго
измерения не даёт. Смысл — сравнить два независимых списка: расхождение показывает, где искать
пропуск, совпадение — довод в пользу полноты._

_Гейт в долге — таблицу удалить целиком и оставить вместо неё строку `н/п` с причиной; тогда человек
знает, что второго измерения у него нет._

## Точка правки
_Конкретное место и почему именно сюда._

- `src/tariffs.ts:priceFor` — здесь и только здесь сходятся `base`, `discount` и `total`;
  надбавка встраивается в этот же расчёт, чтобы порядок «база → скидка → надбавка → итог»
  остался явным и читаемым в одном месте (инвариант задачи)
- `src/oversize.ts` (новый) — правило и ставки живут отдельно от тарифной таблицы по прямому
  требованию claim-8; `src/zones.ts` — единственный существующий прецедент модуля такого рода
  в проекте, разумно повторить его оформление (doc-комментарий, именованный экспорт функции)

## Риски
_Риск, уже записанный вопросом в задаче, здесь не повторяется — одна неопределённость живёт
в одном месте._

- Форма `Quote` без поля `surcharge` для обычных отправлений требует условного добавления
  ключа (например через spread `...(surcharge !== undefined ? { surcharge } : {})`), а не
  присвоения `undefined` — обычное присваивание `quote.surcharge = undefined` создаёт ключ,
  который `Object.keys` всё равно вернёт, и claim-1/claim-5 упадут на этом различии
- Порядок слагаемых в `priceFor` — инвариант, проверяемый только чтением на ревью (не тестом
  впрямую): численно `base − discount + surcharge` и любая другая перестановка тех же операций
  дают одно и то же число, поэтому легко случайно нарушить заявленный порядок кода, не уронив
  ни одного теста
