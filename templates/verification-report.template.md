# Отчёт приёмки: ‹название витка›, chunk ‹N›, попытка ‹K›

> Этап 6. Заполняет **независимый рецензент** — не тот агент, что писал код, и на более сильной
> модели. Ищем расхождения, не подтверждения. Гейты прогоняются здесь заново: файлы исполнителя —
> свидетельство этапа 5, не источник вердикта. Как считается вердикт — `SDLC.md` → этап 6.
> Имя файла: `verification-report-‹N›-attempt-‹K›.md` — попытка не перезаписывает предыдущую.

- **Diff:** `chunk-‹N›-attempt-‹K›-diff.patch`, база ‹base_sha›, дерево ‹head_sha›
- **Сверка с деревом:** перегенерированный `git diff` совпал с патчем: да / **нет — passed=false**
- **Задача:** `intent.md` (‹название витка›) · **План:** `plan.md`, одобрение от ‹дата›
- **Набор гейтов:** от ‹дата последнего изменения — совпадает с журналом набора: да/нет›
- **Долг набора:** ‹все строки закрыты — см. таблицу «Долг» в наборе› / ‹незакрыты: имена гейтов›

## Гейты

_Строка на каждый включённый гейт, помеченный в наборе «этап 6». Имя гейта дословно из набора.
«Результат» — фактически выполненная команда, код возврата, счёт: гейты прогоняются на этом этапе
заново, вывод этапа 5 годится только для сверки._

| Гейт | Статус | Результат |
|---|---|---|
| Сборка | ‹✅/❌/⏭› | ‹команда · код возврата · время› |
| Тесты | ‹✅/❌/⏭› | ‹команда · N passed / M failed› |
| Scope: файлы вне плана | ‹✅/❌/⏭› | ‹список / нет; `.sdlc/**` исключены› |
| Анти-обход тест-гейта | ‹✅/❌/⏭› | ‹маркеры отключения, удалённые тест-файлы, нетто по декларациям› |
| Ревью независимым агентом | ‹✅/❌› | ‹модель, что подано на вход; итог — §2› |
| ‹прочий включённый гейт этапа 6› | ‹✅/❌/⏭› | ‹результат› |

**Неприменимость** — единственный способ получить `passed=true` при `⏭`. Только про то, что гейт
бессмыслен для этих изменений; «не было окружения» — не она. Строк нет — удали таблицу ниже
и оставь единственную строку «строк неприменимости нет». Строки есть — заполни таблицу
(колонка «Утвердил» без имени = артефакт не заполнен):

| Гейт | Почему бессмыслен для этого diff'а | Утвердил (человек) |

### Гейты ранних этапов

_Перенос статуса со своего этапа («этап 1», «этап 2», «этап 4», «этап 5»), со ссылкой на
артефакт, где он виден (`readiness.md`, `exploration-report.md`, `plan.md`, журнал chunk'а).
Гейт, не прогонявшийся на своём этапе, получает `⏭` и роняет вердикт. Гейты «этапа 7» сюда
не входят — они отчитываются в handoff'е; гейты «вне витка» — тоже нет, их свидетельство —
собственные артефакты. Включённых строк нет — удали таблицу ниже и оставь единственную строку
«включённых гейтов ранних этапов нет»:_

| Гейт | Этап | Статус | Где виден |
|---|---|---|---|
| ‹гейт› | ‹этап› | ‹✅/❌/⏭› | ‹артефакт› |

## 1. Пункты приёмки

_`✅` — доказано по diff или тестом. `❌` — опровергнуто. `⚠` — доказательство держится
на непройденной проверке. `manual` — пункт с тегом `[manual]` в задаче: по построению не
проверяется этим этапом, не роняет `passed`, переносится в `handoff.md` как открытая ручная
проверка (не путать с `⚠` — тот про несостоявшуюся автоматическую проверку, `manual` про
проверку, которой на этом этапе и не должно было быть). Статус выбирается по тому, **на чём
держится доказательство**: пункт, доказуемый по diff, получает `✅` даже при непрогнанном тесте.
Новые id не создаются, текст пункта не пересказывается — сверка идёт по id, колонка «Пункт»
даёт первые слова для читаемости._

| id | Пункт (первые слова, дословно) | passed | Чем подтверждён (`файл:метод` / тест / hunk диффа) | Что чинить |
|---|---|---|---|---|
| claim-1 | ‹начало пункта…› | ‹✅/❌/⚠/manual› | ‹Файл:метод / ИмяТеста / @@ -N,+M @@ / «[manual] — см. handoff»› | ‹что чинить› / н/п |

## 2. Ревью: что искали опровергнуть

_Углы: построчный скан diff · аудит удалённого поведения · кросс-файловый трейс вызывающих
и вызываемых. Полная процедура — в промпте рецензента._

- Подтверждённое расхождение: ‹что не совпало, с адресом `файл:строка`› / н/п
  _(роняет вердикт независимо от пунктов приёмки)_
- Поведение, не покрытое ни одним пунктом: ‹что именно› / н/п
  _(это ещё и пропуск в приёмочном листе — идёт в запись о дефекте, а не на ближайший по смыслу пункт)_

## 3. Scope

- Файлы вне `plan.files_to_touch` (кроме `.sdlc/**`): ‹список› / нет
- «Чего не делаем» просочилось в diff: ‹что именно› / нет
- **Пути плана без правок** — на каждый одна из двух формулировок, «нет замечаний» не годится.
  Гейт в долге — сверку делает рецензент руками, шаг от этого не исчезает:
  - ‹путь из plan.files_to_touch› — «не потребовалось, потому что ‹причина›» / «не сделано»
  - непокрытых путей нет

## 4. Инварианты

_Нарушенный инвариант роняет вердикт независимо от статусов гейтов. Инвариант, для которого задача
назвала конкретный проходящий тест, закрывается этим тестом — в долге может быть гейт с ассертами,
но не сам факт наличия теста._

- ‹инвариант из задачи› — держится, чем подтверждён: ‹тест / место в diff› / нарушен: ‹где›
- проектных инвариантов в задаче нет: н/п

## 5. Регрессии

_Только откат внешнего поведения: сломанная сборка или тесты, переход пункта из `✅` в `❌`. Новый
внутренний побочный эффект, не покрытый пунктом приёмки, — это §2, а не регрессия._

- ‹что сломалось› / нет

## Вердикт

- **passed:** true / false
- **По каким условиям упал:** ‹перечислить› / н/п
- **action:** continue / retry / blocked_env / escalate
- **Попытка:** ‹K› из ‹бюджет› — при исчерпании retry невозможен, только escalate.
  `blocked_env` попытку **не расходует** — следующий прогон снова `K`, не `K+1` (SDLC.md → этап 6,
  «Красный из-за окружения»)
- **retry_instruction:** ‹что именно чинить в chunk'е› / ‹для `blocked_env` — что и в какой среде
  прогнать, адресовано оператору/инструменту, не исполнителю chunk'а› / н/п
- **carry_forward:** ‹что помнить на следующей итерации› / н/п
- **Кандидаты в запись о дефекте** _(для handoff'а — просматриваются по всем отчётам витка)_:
  ‹строки из §2› / нет
