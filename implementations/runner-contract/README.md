# Контракт рантайма Agent-SDLC v1

Markdown-артефакты — читаемая проекция витка, а не источник состояния. Канонический файл
`.sdlc/<slug>/state.json` соответствует `schemas/agent-sdlc-state-v1.schema.json`; его пишет
только рантайм атомарной заменой. Модель не редактирует state и не считает вердикт.

## Границы ответственности

- Рантайм создаёт попытки, исполняет гейты, хэширует evidence, хранит решения человека и
  вычисляет `verification.passed`/`action`.
- Рецензент возвращает только JSON по `verify-review-v1.schema.json`. Конечный автомат обязан
  применить constrained decoding, затем валидировать схему и адреса evidence. Один repair-запрос
  разрешён; второй невалидный ответ оставляет review-gate в `skipped`.
- Renderer строит `*.md` из `state.json`; ручное изменение проекции не меняет состояние и должно
  быть перезаписано следующим renderer-прогоном.

## Совместимый переход

Пока `state.json` отсутствует, `flow-verdict.py` работает со старым Markdown-протоколом. Если
файл есть, он проверяется первым; Markdown остаётся контрольной проекцией, а не входом
вердикта. Импорт старого витка обязан маркировать недоступные данные `unknown`, а не угадывать.

Reference-инструмент `tools/state_contract.py` проверяет оба JSON-контракта и печатает
детерминированную проекцию verification-отчёта. Внешний Agent-SDLC Runner должен использовать
эти схемы либо их байт-в-байт эквивалент, а не парсить Markdown регулярными выражениями.
