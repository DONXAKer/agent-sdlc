# Проверь результат

Если после полной проверки остались только заранее выделенные `[git-result:*]`, заверши отчёт с passed=false и проверь флоу.
Выполни `git_operation.py prepare`. Успешный допуск передай отдельному Git-маршруту handoff; остальные отказы направь на исправление.

Вход: `<slug>` и явный корень целевого проекта.

Сверь свидетельства с деревом через attempt-evidence.py. Выполни гейты из gates.md. Передай sdlc-reviewer задачу, план, гейты, diff и фактические результаты без рассказа исполнителя. Запиши verification-report-N-attempt-K.md по шаблону. Проверь его через flow-verdict.py --at verify. Провал, пропуск или устаревшее свидетельство не означают успех.

Проверь выбранную базу и её идентификатор в evidence. Для `snapshot` сверяй исходные байты и manifest с SHA-256 плана.
Ревью, scope и base-check используют тот же снимок. Потеря или изменение снимка блокирует приёмку.

Проверь квитанцию предусловий каждого chunk и её хэш в evidence. Отсутствие квитанции не подтверждает порядок подготовки.
Сверь область закрытия долга с текущим slug. Переносимый риск требует причину и условие пересмотра.

## Общий контракт OpenCode

Прочитай ../sdlc-run/references/SDLC.md и нужные формы из ../sdlc-verify/templates.
Пути ресурсов разрешай относительно файла навыка, а пути проекта передавай явно и заключай в кавычки.
Служебные Python-инструменты находятся в ../sdlc-verify/tools. Сначала прочитай их справку и контракт аргументов.
Источник состояния — .sdlc/<slug> целевого проекта. Не восстанавливай решения из памяти диалога.
Если найден state.json либо признаки проработки Runner v2/v3, остановись и направь продолжение в Runner. Не преобразуй виток.
Сохраняй пять обязательных гейтов и бюджет из sdlc-constants.json. Не подменяй результат проверки заявлением модели.
Отсутствующий инструмент или проверяющий — блокер. Не объявляй такой этап пройденным.
Сохраняй разрешения человека. Внутри одобренной области выполняй обратимые действия без повторного согласования.
Изменение входов отменяет относящееся к ним одобрение или проверку. Не придумывай решения человека.
Вызывай указанных субагентов с новым контекстом и минимальными входами. Не передавай им историю исполнителя.
Отдельный агент той же модели не является независимой моделью. Инструкция запрета записи не создаёт песочницу.
Здесь нет hooks Claude Code или защит Runner. Scope проверяется по фактическому diff; техническая изоляция не заявляется.
Текст артефактов пиши по-русски. Не закрепляй бизнес-правила, пути или ответы конкретного тестового задания.


## Первичные доказательства

При runtime-критериях разрешён также пакет `review_evidence.py` по схеме `review-evidence-v1`.
Manifest перечисляет claim-ID, путь, raw SHA-256, вид, источник и ревизию HEAD + SHA-256 патча.
Проверяй ZIP и квитанцию программой. Читай только перечисленные первичные файлы.
Допускаются JSON-снимки, stdout, SQL-трассы, изображения и фикстуры. Рассказ исполнителя, прежнее ревью и история диалога запрещены.
Несовпадение ревизии требует новой проверки применимости и нового доказательства. Manifest не присваивает passed.
Для finding сохраняй адрес объекта в патче или intent.md/plan.md/gates.md. Дополнительная ссылка допустима только по закреплённому пути и SHA-256.
Передавай ZIP побайтово вместе с квитанцией. Нормализация CRLF/LF не сохраняет raw SHA-256.

Успешный `flow-verdict.py --at verify` сохраняет отдельную машинную квитанцию результата.
Квитанция связывает slug, chunk, попытку и SHA-256 отчёта. Последующий отказ не скрывается прежним passed=true.
Метрики подтверждают успех только по последнему машинному результату того же отчёта.
Исторический текстовый PASS без квитанции показывается отдельно. Метрики сохраняют exit 0 и не утверждают бюджет автоматически.

Загрузи нужный навык инструментом skill по имени sdlc-*.
Вызывай роли инструментом subagent с новым контекстом.
Передай роли абсолютный путь к установленному ../sdlc-run/references/SDLC.md.
