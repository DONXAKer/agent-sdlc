## Во что упёрлись

**v1 — осиротевший код от неполного SEARCH/REPLACE.** `test/oversize.test.ts:39` не
разбирается парсером: после каждого валидного `describe(...)`-блока в файле висит хвост
без своей обёртки (`const quote = priceFor(order); assert.deepStrictEqual(...)` без
`describe`/`it`) — след того, что на одном из шагов SEARCH накрыл только ЧАСТЬ старого
блока теста, а плоский (без обёртки) старый хвост остался. Гейт «Сборка» фикстуры на тот
момент грузил только `src/*.ts` — поломка теста была невидима ремонтному циклу шага и
всплыла только на прогоне тестов этапа 6 (регрессия по всему тест-раннеру,
`triggerUncaughtException`), когда чинить в рамках той же попытки уже нечем.

Правка раннера по итогам этой находки: гейт «Сборка» расширен на `test/*.ts` — проверяет
синтаксис (`stripTypeScriptTypes` из `node:module`, парсинг без исполнения — `import()`
теста реально ЗАПУСКАЕТ `describe`/`it` даже вне `node --test`, слил бы гейты «Сборка» и
«Тесты»), не исполнение. Подробности и коммит — `Agent-SDLC-Runner/docs/model-runs.md`.

**v3 (после починки гейта) — другая ошибка, но снова своя.** Дубль объявления `const zone`
в `src/tariffs.ts:168`. Гейт **поймал сразу** — шаг ушёл в ремонт (1 исходный + 2 ремонтных
запроса из бюджета), но модель не смогла починить дубль за отведённые попытки, шаг остался
❌. Третий шаг (`test/oversize.test.ts`) тоже красный отдельно — «фрагмент встречается 2
раза», сработал штатный предохранитель `Edit` от неоднозначной правки на файле, где похожие
блоки повторяются.

## Итог

**Вердикт: ❌ этап 5 по качеству, ✅ по закрытию — 0 зелёных из 2 измерений.** Модель
доводит `stepFill`-цикл до конца (не блуждает, не отказывается от записи — тот порог,
который валит `devstral-small-2`/`gpt-oss-20b`), но в обоих измеренных прогонах вносит
runtime-ломающую ошибку в СВОЙ ЖЕ код (осиротевший блок теста; дубль объявления), причём
РАЗНУЮ каждый раз — не повторяющийся баг одного класса, а общая ненадёжность на объёме
задачи. Починка гейта «Сборка» под `test/*.ts` (найдена именно на этой модели) — реальный
вклад в конструкцию раннера независимо от итогового вердикта самой модели: класс дефекта
v1 теперь виден ремонтному циклу шага сразу, а не только на этапе 6.

Серия <3 — рано делать окончательный вывод «не тянет». Кандидат на следующий замер: та же
явная форма шага-теста с ожидаемыми значениями, что и у `qwen3-coder-30b-a3b` — снижает
свободу модели выдумывать структуру теста заново на каждой попытке ремонта.
